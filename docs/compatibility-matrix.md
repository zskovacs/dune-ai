# Configuration compatibility and rule overrides

This document describes **official source compatibility**, separately from the
composer's implemented subset. A configuration can be recognized, validated for
the implemented composition scope, and still have no playable game engine. No
Dune configuration is playable in SLICE-001. Unsupported resolution must produce
an explicit diagnostic, never silently approximate a rule or run the toy game.

The [rules index](rules-index.md#citation-convention-and-document-inventory)
defines I/A/X/M/U/S/B as exact local PDF filenames. **Every page below is a
one-based PDF page**, not the restarted printed numbering in Uprising supplements.
These citations identify the supplied editions; no later FAQ is assumed.

## Unresolved questions and safe resolution boundary

These are explicit gaps or ambiguities in the supplied evidence, not new official
incompatibility rules. A future slice must resolve them before supporting affected
profiles. The composer may conservatively reject profiles outside its verified
scope while preserving them as recognized options.

| ID    | Question / evidence                                                                                                                                                                                                   | Required handling                                                                                                                                       |
|-------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| RQ-01 | Epic changes threshold to12 while Go to11 prescribes11 or 4p10; no precedence between the two is given. (X p.10; M p.12.)                                                                                             | Reject simultaneous selection as unresolved configuration; do not claim an official mutual exclusion.                                                   |
| RQ-02 | Bloodlines relocates Commanders for full Ix in the Tech section, even though Ix can cover Commander locations without Tech. (B pp.3,7; U p.18.)                                                                       | Preserve the documented full-Ix+Tech case. Explicitly review no-Tech placement scope before resolving that broader combination.                         |
| RQ-03 | Dreadnought control names original Carthag; Uprising changes control location to Spice Refinery. Uprising declares Ix compatibility without a detailed dreadnought-control renaming instruction. (X p.6; U pp.10,18.) | Record required adjudication/FAQ check for gameplay; representative board composition does not implement this effect.                                   |
| RQ-04 | Ilesa needs original Foldspace cards; actual leader/Reserve implementation and user ownership constraints are outside complete rulebook metadata. (U p.18.)                                                           | Track external component requirement; do not pretend enabling Uprising+Ix supplies a complete playable catalog.                                         |
| RQ-05 | Six-player combinations may contain awkward uncovered card interactions; supplement explicitly warns of this and refers to FAQ/adjudication. (S p.12.)                                                                | Keep six-player recognized until its role-specific setup/actions and source-backed effects are implemented; never approximate it as six ordinary seats. |
| RQ-06 | Rulebooks list component totals and selected names, not a complete versioned per-card inventory/effect specification. (I p.3; X p.2; M p.3; U p.3; B p.2.)                                                            | Keep sample catalog explicitly partial. Verify individual content from permitted evidence before gameplay import.                                       |
| RQ-07 | Rules provide optional conflict/card blends and recommendations, so a single “all products” profile is ambiguous. (U p.18; S p.13; B p.7.)                                                                            | Use explicit content profiles; record whether recommended exclusions or a declared alternate selection is used.                                         |

No broad mutual exclusivity between the three expansion products is asserted by
these sources. The exclusive choices the architecture must represent are one base
board definition, one player format, one selected target/scoring policy and one
resolved definition per replacement target. The requirement for unambiguous
definitions is an engine invariant, not an invented tabletop rule.
