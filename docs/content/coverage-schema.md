# Content coverage audit contract (initial S1)

`coverage/inventory.json` is the sole manually authored source for audit quantities and evidence. It is an **offline audit** and is never loaded into engine rulesets or included in canonical game identities. This S1 revision contains sources and expectations only; empty `content`, `capabilities`, `interactions`, `batches`, and `configurations` mean **not audited yet**, not complete or supported. Task 2 adds the strict Python model and validator; this document describes the initial authoring contract and must be reconciled with that implementation.

## Root and stable references

The root has `schemaVersion: "dune-content-coverage-v1"`, `auditRevision` (this audit's authored revision), `repositoryRevision` (the Git baseline assessed), and the seven named collections. `src-*` and `exp-*` IDs are stable, globally unique within their namespaces. Later records refer to these IDs; renaming one requires a deliberate migration of references. `auditRevision` does not change an engine fingerprint, content version, ruleset revision, or replay format. Keep these collections in deterministic ID order when editing. This initial data has a source-first, then product/scope order; a later formatter may normalize that order without changing IDs.

## Source records

Each `source` has `id`, `kind`, `title`, exact `locator`, `revision`, nullable `sha256` and `pages`, `products`, `claimTypes`, `completeness`, `verification`, `rights`, and `notes`. `src-I`, `src-A`, `src-X`, `src-M`, `src-U`, `src-S`, and `src-B` refer to the seven exact local files and hashes in [the rules index](../rules-index.md). PDF pages and evidence pages are **one-based PDF pages**. A file hash identifies bytes, not correctness of every face. Web revisions are observation dates unless an immutable commit is given. Community identity discovery, quantity, printed face semantics, module applicability, and official rulings are distinct claims. `rights` is an audit finding about permission evidence; it grants no reuse. No source record implies complete inventory or automated import suitability.

## Inventory expectations

An expectation contains `id`, `product`, `edition`, `category`, nullable `tier`, `expectedCopies`, nullable `uniqueDefinitions`, `unit`, `basis`, `scope`, at least one `evidence` locator (`sourceId`, one-based `page`, `locator`), and nullable `note`. Product values are exactly `Imperium`, `Uprising`, `RiseOfIx`, `Immortality`, and `Bloodlines`. Categories use current `ContentCategory` names in `ContentDefinition.cs`; `GameplayComponent` is an **audit-only** category for pieces/tokens outside the runtime catalog enum. It does not register an engine definition. `expectedCopies` is a nonnegative official quantity for the stated basis and scope. `uniqueDefinitions` is `null` when a component total gives no unique-face total; never fill it from a community row count. Known distinct starter identities, three Reserve identities, eight physical Leader cards, and 22 printed board locations are stated only where the source establishes them.

`scope` separates boxed pools, boxed tier/identity subsets, ordinary per-player recipes, standard setup components, and excluded solo/two-player, Epic, six-player, CHOAM, Tech, or leader-specific material. A subset **overlaps** its parent boxed pool and must not be summed into it. The 18 original Conflicts split 4 + 10 + 4, while ordinary setup selects 1 + 5 + 4 = 10; the latter is not the box total. Original Reserve cards split 8 + 10 + 6 = 24. Original starter copies are four ten-card player sets = 40; each set has seven identities and 2 + 2 + 1 + 2 + 1 + 1 + 1 = 10. Three-player games use only 30 starter copies. The original board's 22 locations are named spaces, not loose cards. Alternative wood/plastic Bloodlines Commanders form a seven-unit usable pool, not fourteen usable units. Uprising likewise has four boxed ten-card starter sets and a distinct ten-card per-player recipe (U p.3). Ix has four boxed Control the Spice cards but only one per player in excluded Epic mode (X p.2); Immortality has eight boxed Experimentation cards but replaces two starters per player (M pp.3,5).

Do not turn a count into a face, effect, eligibility predicate, ability, or readiness claim. Module-scoped totals remain physically boxed totals even when the selected configuration excludes them. Keep unclear edition effects, print differences, and rights disputes as explicit limitations. A future complete pool requires identity-level, quantity-level, applicability-level, and face-level evidence separately.

## Updating restricted local evidence

Acquire source files personally from the publisher or a legitimately held copy. Keep PDFs, scans, extracted text, images, spreadsheets, and scraped data in ignored local storage; do not commit them or fetched website bodies. Record the exact edition/URL or owner-held provenance, retrieval date, SHA-256 (`sha256sum <file>`), page bounds (`pdfinfo <file>`), and one-based page/section for each claim. Compare the new hash with the pinned source record. Inspect relevant page renders for symbols, tiers, layout and obscured faces; text extraction is only a search aid. Manually enter minimal, independently reviewed metadata and cite the claim. Check official FAQ/errata and module exclusions, note disagreements without choosing a convenient count, and review reuse rights before copying any text or art. Validation and generated reports must run offline, and missing optional local copyrighted files must be reported as unavailable evidence without fetching them automatically.
