# SLICE-002: base setup and runtime state

The user request is the acceptance specification and authorizes implementation now.
Implement original Imperium Standard competitive 3/4-player initialization, fixed or
seeded-random unique leaders, immediately before Round Start. No actions, effects,
round execution or expansion mechanics. Keep Toy operational.

## Evidence and content boundary

Use local 2020 rulebook PDF pp.3–8 and 17–18 plus player aid p.2.
There are twelve troops per player (16 cubes less four influence cubes), three in
garrison and nine in supply; zero initial spice/Solari, one water, two Agents and

The bundled catalog is incomplete and third-party reuse permission is absent.

## Design decisions

- Preserve configuration/composition APIs and gameplay NotImplemented. Attach an
  immutable typed setup definition only for the supported, unchanged base modules;
  never execute prose recipes or ignore replacements/extra modules.
- Separate static definitions from episode-local CardInstance identity. Ownership
  and visibility belong to zones; controlled move/draw/shuffle operations retain
  IDs. All mutable runtime collections are private with read-only views.
- Typed state covers players, board/occupancy/control/spice, shared zones, conflict,
  alliance tokens, Mentat, resources, status/phase and temporary effects. Typed
  module extension objects permit future state without unused expansion fields.
- Use an instance-local seeded System.Random adapter with a restorable raw draw
  counter. Bounded sampling and Fisher–Yates are explicit. Main and leader RNGs
  use the existing separate configuration seeds. Scope replay to pinned runtime,
  setup schema, ruleset and content versions. No dependency or custom PRNG needed.
- Initialization validates configuration/definition identity and inventory before
  creating state. Errors yield no partial state. Content count checks alone do not
  establish authenticity; provenance/status/completeness are required too.
- Explicit detached immutable observation projection includes public zones/counts,
  only own private cards and no seed, RNG, config, deck ordering or hidden IDs.
- Trusted canonical snapshots include all runtime state and random checkpoints,
  schema/runtime/ruleset/config/content identities. Hash deterministic JSON with
  SHA-256. Hidden debug data is never attached to observations. Future replay
  reconstructs setup then applies versioned ordered actions; no event framework.
