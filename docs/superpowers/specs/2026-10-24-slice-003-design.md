# SLICE-003 design

Implement the user's SLICE-003 specification on the existing setup/runtime model.
The requested base is unchanged original Imperium (2020), Standard, competitive
3–4 seats, fixed/random leaders and seeded randomness. Stop before Combat rules.

## Evidence and support boundary

Existing content has names/counts, not executable card definitions. Public authentic
initialization stays blocked by the incomplete 67-card/40-Intrigue/18-Conflict/eight-leader
inventory. No configuration is fully playable or RL-ready. An explicitly synthetic
inventory may exercise verified operations in tests/benchmarks and a CLI development
preview; never replace missing official effects or leader abilities with fixture bonuses.
An unsupported effect reports a diagnostic before action mutation. A partial CLI
scenario is allowed by the user's final acceptance paragraph when authentic content
or leader support blocks a full first round.

## Architecture

Retain GameState, CardZone and SeededRandom ownership and identity. Add explicit
RoundStart/PlayerTurns/CombatBoundary phases, turn status and pending effect/decision
state. Immutable typed gameplay definitions keyed by stable content/space IDs are
separate from descriptive metadata. Resolve only the unchanged base ruleset; future
occupancy exceptions attach to resolved rules rather than a global assumption.

Use a TurnEngine facade with Observe(player), LegalActions(player), Step(action),
RoundStart, trusted snapshot/hash and ordered action replay. One placement action
selects card + destination; effect-order, optional payment, deployment count,
acquisition and ending Reveal are subsequent actions. Deterministic independent
primitive gains can drain automatically; do not choose strategically relevant order.
Reveal purchases are available between effect resolutions. Distinguish active turn
owner and decision owner via effect execution contexts and decision frames.

Validate complete selected effect graphs before placement/reveal/acquire mutation.
Invalid/unsupported input leaves cards, resources, RNG, pending work and history
unchanged; invariant corruption throws rather than masquerading as illegal input.
No event-sourcing framework, reflection dispatch, custom scripting language, new
runtime dependencies, speculative expansion implementations or TDD sequencing.

Public observations add only visible physical IDs, decision summaries and own legal
actions. Trusted snapshots include all pending work and RNG/history needed for
comparison; never return those to agents. Replay binds runtime, engine, rules,
content/support versions, seeds, configuration and initial trusted state identity.

## Reviewed execution boundary

Minimum card definitions: Dune, the Desert Planet permits Spice Trade and has no
Agent effect (I p.3 visible icon, p.10 example); its obscured Reveal box is gated.
Signet Ring permits Landsraad/City/Spice Trade and reveals 1 Persuasion (I p.3),
with Agent use gated for all unsupported leaders. Liaison, Spice Must Flow,
Fremen Camp and Sardaukar Legion use the complete sourced faces described above.
Other starter permissions visible in I p.3 may be represented but unverified
Agent/Reveal boxes produce unsupported diagnostics. No undocumented bonuses.
Sell Melange (A p.2) demonstrates a single chosen exchange of 2/3/4/5 spice for
6/8/10/12 Solari; payment precedes rewards.

CLI preview explicitly initializes the existing synthetic inventory, reveals a
synthetic Conflict and draws real named starters, chooses only verified Agent
moves (e.g. Dune -> Secure Contract/Imperial Basin), logs a replay, then reports
the first unsupported card/leader dependency without mutation. A verified complete
Player Turns trace is exercised with explicitly test-only synthetic effect fixtures,
not claimed as an authentic CLI first round. The exact CLI partial trace may vary
with seed and must report why it cannot reach Combat.

All real leaders need an audited executable passive + Signet contract before any
turn action can run under that leader. Unsupported passives cannot be omitted on
otherwise supported actions. Synthetic leaders are explicitly test/development
inventory with no official identity, not replacement abilities for real leaders.

Existing physical IDs correlate with sorted definitions. Do not expose these raw
IDs to policies: use deterministic opaque episode-local card handles with a
mapping independent of definition ordering (or content+copy selectors for visible
cards only). Replay and snapshot must preserve/derive the mapping; observation
calls cannot consume RNG or change future action identities. Test correlation
redaction, including inactive legal actions and failure diagnostics.
