## Selected-card contract and alternatives

Controller recommendation, proposed for approval:

```csharp
public sealed record SelectedTrashEffect(ImmutableArray<Effect> OnTrashed,
    bool Optional = true) : Effect;
public sealed record SelectTrashCardAction(int PlayerId, int DecisionId,
    CardZoneId Source, CardSelector Card) : GameAction(PlayerId);
public sealed record DeclineTrashAction(int PlayerId, int DecisionId)
    : GameAction(PlayerId);
```

JSON allowlist tags: `$effect: selected-trash`, `$action: select-trash-card`, and
`$action: decline-trash`. Existing tags and selector shape remain unchanged.
Empty `OnTrashed` represents an ordinary trash instruction; nonempty children are
the benefit obtained only after successful trash. `Optional=false` removes decline;
it does not authorize skipping trash when no target exists. This slice's only new
official consumer is `SelectedTrashEffect([new DrawEffect(2)])` on Selective Breeding.
Do not reinterpret `TrashSelfEffect` as this operation or automatically make it optional.

Eligible zones for this original trash effect are exactly the chooser's Hand,
Discard, InPlay, in that deterministic order, using existing `Selectors(zone)`.
Deck, Intrigue, shared piles and opponents' zones are excluded even if supplied by
an otherwise well-formed action. No configurable zone DSL is necessary for this
consumer. A future narrower printed instruction must introduce an explicit typed
restriction and its own evidence before reusing a broader set incorrectly.

The target owner is the decision owner and card-cost payer. For this operation,
chooser and payer must be the same player; a different recipient may receive its
children through existing role bindings. Unsupported role combinations fail closed,
without consulting another player's private cards. `ForPlayerEffect` can still
transfer the entire decision to another owner without changing the normal turn.

Add trusted value records in `EffectExecution.cs`:

- `SelectedTrashOption(CardZoneId Source, CardSelector Card, CardInstanceId Instance)`.
- `SelectedTrashDecision(int Id, ImmutableArray<SelectedTrashOption> Targets)`, stored
  as nullable init property `DecisionFrame.SelectedTrash`.
- `SelectedCardTarget(CardInstanceId Instance, ContentId Definition, CardZoneId Source,
  int OwnerId)`, stored as nullable init property `EffectContext.SelectedTarget`.

These are payloads of the existing decision/context, never another executor.
Issue the decision ID from `++_nextEffectId` when activating the effect. It is an
execution serial unrelated to allocation IDs and survives replay through the
existing counter. Freeze the selector-to-instance bindings at activation. At Step,
require the current selection ID, permitted owner/zone, recorded selector, live
zone membership and the same physical instance. If a duplicate has moved and
indexes compact, reject instead of silently selecting a replacement. Reusing an
old action during a later otherwise identical decision also rejects.

This is bounded O (own eligible cards) data built once per decision. Legal enumeration
uses the frozen bindings and shared validator; it must not clone or hash state per
candidate. The policy sees only `DecisionId`, zone and `CardSelector` in its actions.
Generic pending summaries contain the decision kind/decline availability, not the
trusted bindings. Existing interchangeable-copy selectors remain sufficient; no
new global opaque-card ID system or per-card modifier support is introduced.

Alternatives rejected: a giant placement action would flatten later decisions and
ordering; an unbound zone/selector would not reject stale duplicate choices; a new
selection framework/global public physical ID would duplicate existing architecture
and violate privacy. Adding a decision-bound payload is the smallest supported change.

## Card movement and ownership

Add a focused partial file `src/Dune.Engine/Turns/TurnEngine.Trashing.cs` for target
enumeration/validation, selected-trash commit and shared trash routing. Use existing
`CardZone.MoveTo` for the actual move; no mutable duplicate stock or ownership ledger.

Resolve a destination using `GameSetupDefinition.Reserves` and exact matching shared
Reserve zone ID; use category/definition consistency as validation, not name prefixes
or executable face availability. This works with an empty destination stack.
Arrakis Liaison, The Spice Must Flow and Foldspace route independently to their
own stacks. Other eligible ordinary cards route to `Shared.Trashed` (game-box
equivalent, excluded from draw/refill/owned-card scoring). Missing or inconsistent
Reserve routing is a content/invariant error detected before movement.

Both selected trash and self-trash use this destination operation. Self-trash retains
its executing-source semantics and ordinary already-trashed idempotence; already
returned Reserve sources similarly do not move twice. A card in shared stock or
another player's zone must not become newly eligible for a pending self operation.
Do not grant a reward for a failed card payment or implement future self-trash costs.

On successful selection, create `SelectedTarget` from the pre-move binding; preserve
`SourceCard`, `SourceDefinition`, `Space`, initiator, payer, chooser and recipient.
Move the same instance, clear the decision, push `OnTrashed` as a child using the
existing PlayerOrdered mode, and call `ContinueTurn`. The move precedes all children;
the complete child frame precedes its suspended parent. Further Acquire/Signet source
rebinding still describes its own executing source; selected-target provenance does
not replace it. Zone ownership changes exactly as existing movement defines; accepted
actions/reconstruction retain history without adding an ownership event store.

## Preflight and state safety

Before every recognized action mutation, validate the whole selected operation and
suspended mandatory work. Selection must check target, destination, OnTrashed support,
generated descendants, resources, Influence, permanent/unique operations, Intrigue
stock, Reserve demand and later reward recipients. No RNG, card move, frame clear,
counter increment or history append occurs on rejection.

Extend existing traversals deliberately: graph shape/Normalize/Support; faction
projection and footprint; resource/choice/payment and permanent-operation walkers;
acquisition/Intrigue/special-operation reservations; context/frame invariants. An
optional unselected OnTrashed branch contributes no mandatory demand and no future
return. A mandatory branch must be proven executable before activation. Validate
malformed children/cycles independently of optionality. Unsupported children in an
optional success branch suppress selection, while legal decline stays available;
return generic owner-scoped diagnostics. Do not broadly rewrite existing choice support.

For a validated Reserve target only, thread one explicit projected return through
`ValidateRemaining`, stock validation and resource-choice feasibility that calls stock
validation. This is a read-only +1 for the exact destination/definition after the
selected trash boundary, including generated acquire children and suspended parents.
The instance is still moved only after the entire selected branch passes. Unselected
optional trash is never stock, and an earlier acquisition cannot use a later return.
After commit, ordinary live stock checks see the returned instance naturally.

Keep feasibility bounded. Count compulsory selected-trash demand against currently
eligible own cards; account for the candidate's removal before later mandatory
selection. Do not invent hidden future draws to satisfy target availability. If
multiple choices, source-sensitive self-trash or future mandatory returns require
unproved joint/order analysis, return an explicit Unsupported gate before the
initiating action. The authentic Selective Breeding path cannot hit that gate merely
because it offers an optional trash/draw. No combinatorial solver or full-state clone.

Distinguish Illegal (wrong owner/ID/zone/target/timing/decline), Unsupported (a well-formed
branch or composite not proven executable), ContentError (invalid authored graph or
destination contract), and unexpected invariant exceptions. Rejection preserves trusted
canonical state/hash, all zones/resources, both RNG checkpoints, frame/counter state,
accepted history and replay identity. There is no arbitrary-exception rollback claim.
