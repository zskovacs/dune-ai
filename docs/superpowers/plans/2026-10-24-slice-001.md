# SLICE-001 Implementation Plan

> **For agentic workers:** Use Superpowers task-by-task execution and independent reviews. Repository TDD overrides
> apply.

**Goal:** Resolve sourced, representative Dune configuration metadata without claiming gameplay readiness.

**Architecture:** Existing Engine owns Configuration, Content and Rulesets namespaces. Immutable module contributions
explicitly add or replace named setup definitions. JSON catalog metadata and ordered canonical hashing use the .NET
standard library.

**Tech Stack:** mise-pinned .NET 10, System.Text.Json, immutable collections, SHA-256, existing xUnit v3.

**Spec:** `docs/superpowers/specs/2026-10-24-slice-001-design.md` and the user's SLICE-001 request.

## Global Constraints

- Local seven PDFs are primary mechanics authority; every rule has PDF/page evidence.
- No full gameplay, full catalog, effects DSL, new dependencies or infrastructure.
- Preserve Toy, existing locks/tool pins, user AGENTS changes and AGENTS.override intent.
- Configuration validation is distinct from playability; all Dune outputs remain nonplayable.
- Use mise tasks; focused tests do not require red/green sequencing.

## Review Focus

- Unknown enum values, null/default collections and malformed serialized configurations reject clearly.
- Set ordering and seed changes cannot alter semantic ruleset identity; metadata changes must.
- Competing module replacements fail independently of registration order.
- Content filters cannot silently remove fixed leaders or admit incompatible content.
- Official compatibility recognition cannot imply complete rules/gameplay implementation.

## Contract decisions (plan review amendments)

- `ConfigurationSupport` = Unrecognized/Recognized/Validated; separate
  `GameplaySupport` = NotImplemented/Playable. This slice always returns NotImplemented.
- `ResolutionResult` contains Support, immutable Errors (Code, Path, Message),
  nullable Definition; failures never expose a partial Definition.
- `GameConfiguration` records BaseGame, immutable Expansion/OptionalModule/RuleVariant
  sets, GameMode, PlayerConfiguration(Format, Count), LeaderSelectionConfiguration,
  ContentSelectionProfile, RandomSeed. Reject unknown enum values, null nested records,
  default arrays, duplicate set items and malformed IDs through validation.
- IDs are distinct record structs for ContentId, ModuleId and DefinitionId.
  `RuleDefinition` has DefinitionId, DefinitionKey(DefinitionKind, Slot), Value,
  immutable source references. Kinds cover BoardLayout, BoardSpace, StartingDeck,
  Resources, ConflictDeck, CardPool, LeaderPool, Mechanic, VictoryCondition, Setup.
  Values describe selections/recipes; they are metadata, never runnable effects.
- `RuleContribution` carries a RuleDefinition and nullable expected prior DefinitionId.
  Add requires vacant key. Replace requires that exact prior ID at that key and a
  dependency path to its owner. Two sibling writers to one key fail even if an
  incidental registration order could make one succeed. Validate graph before merge.
- `RuleModule` carries stable ID, revision, dependency/incompatibility ID arrays,
  contribution array; `RulesetComposer` accepts explicit modules/catalog for graph
  tests, and a default factory selects builtin modules through explicit configuration
  branches. Sort topological peers by ordinal ID; reject missing deps/cycles/duplicates.
- Supported composition scope: competitive 3/4 only; Standard original base,
  original+Ix, original+Ix+Immortality; Epic original+Ix with/without Immortality;
  Standard Uprising base, Uprising+Ix, Uprising+Bloodlines with/without Tech,
  Standard Uprising+CHOAM. GoTo11 only original+Ix+Immortality Standard for now.
  Other recognized combinations return unsupported-scope errors, not invented official bans.
- Source-backed representative selections: IX PDF3 original upper-right overlay;
  Uprising PDF18 folded overlay/virtual observation posts; Immortality PDF5 two
  Experimentation replacements; IX PDF10 Epic target12/conflicts0/5/5/Control Spice;
  Immortality PDF12 Epic override retains10 deck +Control Spice in discard.
  Uprising Bloodlines PDF3 conditional pool; Bloodlines PDF6 Tech opt-in/exclusions;
  Uprising PDF16 CHOAM opt-in. Task1 ledger supplies all exact references.
- Fixed leader assignments require exactly one known eligible leader per seat,
  unique seats/IDs. Random/drafts validate ordered seats, candidate IDs, uniqueness
  and sufficient pool; pool is marked Representative, never official-complete.
  Restriction IDs are reserved but nonempty restrictions reject until implemented.
- Fingerprint format v1 hashes canonical UTF-8 JSON of semantic config (all fields
  except RandomSeed and LeaderSelection.Seed), sorted set fields, ordered seat/draft
  order, sorted fixed assignments, modules/revisions, selected content metadata,
  final definitions and source/override history. Include profile identity/revision.
  Ordinal stable sorting; no culture, clocks or runtime hashes. SHA-256 hex output.
  Reordering registration or sets preserves identity; content/module/value changes alter it.
