# SLICE-004 — Combat, Round Lifecycle & Endgame Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:
> executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete a deterministic supported Dune lifecycle through Combat, subsequent rounds and a structured terminal
result, with explicit authentic-content gates.

**Architecture:** Extend the existing `TurnEngine` resolver/actions with causal frames, typed phase/window continuations
and sourced lifecycle definitions. Reuse physical zones, seeded RNG, observations, replay, Combat strength and the
existing episode runner. Synthetic scenarios exercise complete execution without claiming authentic playability.

**Tech Stack:** C#/.NET SDK 10.0.402, existing BCL collections/System.Text.Json, xUnit v3, BenchmarkDotNet 0.15.8,
existing mise tasks; no new dependencies.

**Spec:** [2026-10-24-slice-004-design.md](../specs/2026-10-24-slice-004-design.md), implementing the user's SLICE-004
request and [SLICE-003.5 findings](../../handoffs/SLICE-003.5-result.md).

## Global Constraints

- Target: Dune: Imperium (2020); no expansions; Standard; competitive multiplayer; 3 or 4 players; deterministic and
  headless.
- Follow `AGENTS.md` and `AGENTS.override.md`: no mandatory TDD, no required failing-test proof. Write focused tests
  alongside or after code where useful; high-risk transitions require thorough behavioral tests.
- Keep one action hierarchy, one resolver, one runner, private episode state and immutable once-composed rules. No
  generic scripts, event sourcing, reflection dispatch, DI framework, new PRNG or speculative allocation work.
- Complete the lifecycle for supported, source-verified mechanics. Unsupported paths reject before mutation; never skip
  effects or prune authentic decks to finish a run.
- No full catalog/leader completion, KH, Graft, expansion gameplay, drafting, Python bridge/training, UI/API/database or
  SLICE-004.5 implementation. Plot timing is recognized but Plot play, including Calculated Hire, remains unsupported;
  the lifecycle fixture enables no Plot cards.
- Source every official rule in `docs/rules-sources.md` with exact supplied PDF/page and behavioral tests. Fixtures
  remain visibly synthetic. No copyrighted scans/art added to Git.
- Preserve Toy, the bounded turn preview, strict JSON options and explicit allowlists. Deliberately version changed Dune
  semantics; no silent old replay reinterpretation.
- Existing APIs remain unless this plan explicitly changes them. No toolchain/package-lock changes or dependencies are
  intended.
- User approval of this design/plan is required before production edits. Planning writes only these two documents;
  implementation starts in an isolated worktree using the installed worktree skill.
- Default execution follows the repository's custom-agent task/review workflow. Use `sp_integration_debugger` for
  P1/P2/reward/lifecycle contracts and `sp_normal_implementer` for bounded definition/CLI tasks; review each task with
  `sp_task_reviewer`, then use `sp_final_branch_reviewer` before final handoff. Load routing/model modules before
  dispatch.

## Review Focus

1. Nested foreign choices or purchases must not expose outer siblings or advance normal turns; tests in Tasks 1–3/5/8.
2. Optional unaffordable branches must remain declineable without admitting unsupported effects or consuming mandatory
   stock; tests in Task 2.
3. Ties and zero-strength seats must produce the same reward model and actual grants, including 3p second-place ties;
   tests in Tasks 7–8.
4. A reward-funded post-win payment and a Conflict Mentat surviving exactly one Recall must survive interrupted replay;
   tests in Tasks 8–9/12.
5. Hidden opponent Endgame conditions, unsupported deck diagnostics and result/replay hashes must neither leak secrets
   nor form a circular identity; tests in Tasks 4/10/12.
